# ADR 0001：使用 PostgreSQL 持久化账号、故事与章节

- 状态：Accepted
- 日期：2026-07-22

## 背景

当前服务把全部用户、会话、故事、章节和修订保存在单个 `store.json` 中。服务启动必须解析整份文件，任意一次写入又必须重新序列化和替换整份文件。数据量增长后，一个故事的修改会阻塞所有用户，并存在进程内存耗尽、文件损坏和多实例写入丢失风险。线上同时缺少普通用户注册入口。

## 决策

线上主存储使用 PostgreSQL，并通过持久化深模块向路由提供账号、书架分页、按所有者加载故事和原子保存故事等能力。

- 用户邮箱使用规范化值建立唯一约束；公开注册只能创建 `reader` 角色。
- 故事元数据与正史状态按故事单独保存；章节和不可变 Revision 分表保存。
- 书架使用 `(owner_id, updated_at, id)` 复合索引和游标分页，不加载正文。
- 章节使用 `(story_id, chapter_number)` 唯一约束，Revision 使用 `(chapter_id, created_at, id)` 索引。
- 有界、结构多变的故事状态使用 JSONB；正文不会与整站账号或其他故事组成一个 JSON 文档。
- `store.json` 适配器继续作为本地兼容模式。迁移工具只做幂等复制和校验，不删除旧文件。
- 上线采用 expand → import/verify → switch → observe 的顺序；本次不执行破坏性的 contract 步骤。

## 备选方案

1. 继续拆分多个 JSON 文件：实现简单，但仍缺少事务、唯一约束、跨实例并发和高效分页。
2. 将每个完整故事放入单个 JSONB：消除了整站文件，但章节 Revision 仍会造成大行更新和读取放大。
3. SQLite：适合单实例本地应用，不适合当前线上多用户与未来水平扩展目标。

## 影响

- 线上部署需要 `DATABASE_URL`，并在切流前执行 schema migration 与旧数据导入。
- 普通读者可自行注册并获得独立书架。
- 书架和故事加载不会随全站数据总量线性增长。
- 故事内部的部分低频状态仍保存在单故事 JSONB 中；若对话或事件量显著增长，可在保持持久化接口不变的情况下继续分表。
