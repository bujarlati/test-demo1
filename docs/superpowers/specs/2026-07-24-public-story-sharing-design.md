# 注册用户小说分享与公共书库设计

日期：2026-07-24

状态：已完成产品设计确认，待实施计划

## 1. 摘要

为续墨增加一个仅限注册用户使用的公共书库。作者可以把自己认为合适的小说立即公开，并获得稳定的分享链接。其他注册用户只能阅读公开小说，不能生成、改写、修史或访问作者侧信息。

公开正文不复制为快照。系统通过独立的发布记录控制访问，并在每次公开读取时查询小说当前正史，因此成功生成的新章节和已提交的正史修订会自动同步。作者取消公开后，公共书库和分享链接立即停止提供正文，但各读者的个人阅读进度保留；重新公开后，原链接和进度继续有效。

## 2. 目标

- 作者能设置账号统一笔名，并公开或取消公开自己的小说。
- 登录用户能从“大家的故事”浏览、搜索和阅读公开小说。
- 分享链接稳定，并在登录后回到原作品。
- 公开版实时读取当前正史，不产生需要额外同步的正文副本。
- 每位读者独立保存章节和滚动位置，不修改作者自己的阅读进度。
- 公开接口采用严格字段白名单，隔离所有作者私有数据。
- 沿用现有举报和管理员能力，支持事后下架。
- 以兼容迁移和功能开关上线，不影响现有私人书架与生成流程。

## 3. 非目标

第一版不包含以下能力：

- 未登录访问或搜索引擎公开收录；
- 点赞、收藏、评论、排行榜、推荐算法或更新通知；
- 读者复制、分叉或继续生成他人的小说；
- 每本小说单独设置笔名；
- 自定义分享短链或自定义 URL；
- 公开历史修订、作者对话、设定集或创作过程；
- 发布审批队列或发布快照版本管理。

## 4. 已确认的产品规则

1. 所有公共书库、分享链接和公开阅读接口都要求登录。
2. 其他用户只有阅读权限。
3. 公开作品同时进入公共书库并生成分享链接。
4. 新章节和已提交的正史修订自动同步到公开版。
5. 每位读者保存自己的章节和滚动位置。
6. 笔名是账号级公开身份；修改后所有公开作品同步显示新笔名。
7. 作者发布后立即可读，无需管理员预审。
8. 公共书库支持标题或笔名搜索、题材筛选和最近更新排序。
9. 作者取消公开后链接立即不可读，但链接标识和读者进度保留。
10. 页面采用“我的书架 / 大家的故事”双入口布局。

## 5. 用户体验

### 5.1 书架入口

登录后的书架顶部增加两个明确的入口：

- “我的书架”：沿用当前私人书架；
- “大家的故事”：进入公共书库。

路由保持可直达：私人书架使用 `/`，公共书库使用 `/discover`。视觉上呈现为同一书架中的页签，路由上分开以支持刷新、返回和分享。

公共书库默认按小说最近成功更新时间倒序排列，每页最多 24 本。页面提供：

- 标题或笔名搜索；
- 题材筛选；
- 最近更新排序；
- 游标分页。

公开卡片显示封面、标题、副标题、题材、笔名、章节数、连载状态和最近更新时间，不显示所有者账号 ID 或创作后台信息。

### 5.2 作者公开流程

作者在自己的故事菜单中选择“公开作品”。

首次公开且账号尚无笔名时，弹窗要求输入 2 至 20 个非空 Unicode 字符的笔名。笔名会被去除首尾空白，不要求全局唯一。确认页同时展示将公开的封面、标题、简介、题材、章节数和当前正史版本，并明确说明：

- 只有登录用户能够阅读；
- 后续正史更新会自动同步；
- 作者私有信息不会公开。

确认成功后，页面显示“已公开”徽标，并提供：

- 打开公开阅读页；
- 复制稳定分享链接；
- 取消公开。

发布操作是幂等的。重复点击不会创建多条发布记录或改变原链接。

作者可以公开 `active`、`paused` 或 `completed` 且至少含有一章成功正文的小说。`archived` 小说不可公开。作者归档一个已公开故事时，系统自动将其转为作者取消公开；恢复故事后需要作者重新公开。

### 5.3 公开阅读流程

稳定分享路径为 `/public/story/:storyId`。未登录用户打开该路径时进入登录页，登录成功后返回经过校验的站内原路径，不接受外部回跳 URL。

只读阅读页复用现有阅读排版与主题设置，但只保留：

- 章节目录和上下章导航；
- 字号、行距、宽度和主题设置；
- 个人阅读进度；
- 举报入口；
- 返回“大家的故事”。

页面不渲染生成、对话、修史、模型设置、故事档案、修订历史或作者控制入口。作者本人通过公开链接访问时也看到公开预览，并额外获得“返回创作版”入口；公开接口的数据范围不因访问者是作者而扩大。

### 5.4 取消公开与重新公开

作者取消公开后：

- 作品立即从公共书库消失；
- 分享链接和公开 API 不再返回正文；
- 读者已加载到浏览器的文字无法被远程追回；
- 数据库中的发布记录和个人阅读进度继续保留。

重新公开后使用同一 `storyId`，因此原链接恢复有效，读者从原进度继续阅读。

## 6. 架构

采用“独立发布记录 + 实时读取当前正史”的结构：

1. 私人小说仍由现有 `xumo_stories`、`xumo_chapters` 和 `xumo_chapter_revisions` 保存，正文只有一份。
2. 新的发布记录只负责判断小说是否允许通过公开接口读取。
3. 专用公开查询直接读取安全列和每章 `current_revision_id` 对应的修订，不调用返回完整作者载荷的 `loadStory`。
4. 专用公开 DTO 只组合公共展示需要的字段。
5. 读者进度保存在独立表中，不写入小说 payload 内的作者阅读进度。

这条边界保证自动同步，同时避免在完整 `Story` 对象上做事后删字段而产生隐私遗漏。

## 7. 数据模型与迁移

新增前向兼容迁移 `004_public_story_sharing.sql`。所有已有小说在迁移后仍为私有。

### 7.1 账号公开笔名

在 `xumo_users` 增加可空列：

```sql
public_pen_name text
```

非空值必须满足去除首尾空白后字符数为 2 至 20。笔名不唯一，避免不必要的抢注和迁移复杂度。

### 7.2 小说发布记录

新增 `xumo_story_publications`：

```text
story_id              text primary key
owner_id              text not null
status                active | author_unpublished | admin_suspended
first_published_at    timestamptz not null
status_updated_at     timestamptz not null
admin_actor_user_id   text nullable
admin_reason          text nullable
```

约束与索引：

- `(story_id, owner_id)` 必须对应同一条 `xumo_stories` 所有权关系；
- 删除小说时级联删除发布记录；
- 管理员字段仅在 `admin_suspended` 时允许有值；
- 为 `status = 'active'` 的列表查询建立部分索引；
- 公共列表的更新时间直接使用 `xumo_stories.updated_at`，确保新章或正史修订自动影响排序。

记录在作者取消公开时不删除，以保持稳定链接。状态转换规则：

- 作者：无记录或 `author_unpublished` → `active`；
- 作者：`active` → `author_unpublished`；
- 管理员：`active` → `admin_suspended`；
- 管理员：`admin_suspended` → `active`；
- 作者不能改变 `admin_suspended`。

管理员恢复会恢复到作品被下架前的公开状态。作者如需取消公开，可在管理员恢复后立即取消；第一版不增加独立的申诉状态机。

### 7.3 公开阅读进度

新增 `xumo_public_reading_progress`：

```text
reader_user_id     text not null
story_id           text not null
chapter_id         text not null
chapter_number     integer not null
scroll_progress    double precision not null
progress_version   integer not null
updated_at         timestamptz not null
primary key (reader_user_id, story_id)
```

约束与行为：

- `scroll_progress` 范围为 0 至 1；
- `progress_version` 必须为正整数并用于乐观并发控制；
- 删除读者账号或小说时级联删除；
- 取消公开和管理员下架时不删除；
- `chapter_id` 不建立级联删除外键，避免章节替换时误删进度；读取时使用 `chapter_number` 回退到仍存在的最近章节。

## 8. 公开 DTO

### 8.1 列表摘要

`PublicStorySummary` 仅包含：

- `id`；
- `title`、`subtitle`；
- `genre`、`tone`、`length`；
- `coverTheme`；
- `status`（连载、暂停或完结的展示值）；
- `authorPenName`；
- `chapterCount`、`currentChapterNumber`、`currentChapterTitle`；
- `latestExcerpt`；
- `updatedAt`。

### 8.2 阅读详情

`PublicStoryDetail` 包含摘要、公开章节和当前访问者进度。每章只包含：

- 章节 ID、编号、标题和预计阅读分钟数；
- 当前修订 ID、当前标题、段落和创建时间。

以下字段禁止进入公开 DTO：

- `ownerId` 和账号内部信息；
- `inspiration`；
- `storyGene`、`endingContract`、`worldBible`；
- `events`、`characters`、`items`、`rules`、`constraints`、`clues`；
- `preferences`、`conversation`、`conversationThreads`、`proposals`、`retcons`；
- `modelConnectionId`；
- 非当前修订和修订原因；
- 生成任务、失败记录、审核记录和模型元数据。

## 9. API 设计

全部接口使用现有会话认证。

### 9.1 作者接口

`PUT /api/stories/:storyId/publication`

```json
{
  "published": true,
  "publicPenName": "青砚"
}
```

- 仅所有者可调用；
- `publicPenName` 只在首次设置或显式修改时提交；
- 发布和设置首次笔名在同一数据库事务中完成；
- 返回当前发布状态和站内分享路径；
- `published: false` 将 `active` 转为 `author_unpublished`；
- 对 `admin_suspended` 发布返回 `409 publication_suspended`。

`PATCH /api/me/public-profile`

- 修改账号统一笔名；
- 修改后所有公开卡片和详情实时显示新笔名。

### 9.2 公共书库接口

`GET /api/public-stories?query=&genre=&cursor=&limit=`

- 仅查询 `active` 且故事未归档的记录；
- `query` 最长 100 个字符，匹配标题或笔名；
- `genre` 必须来自当前题材枚举；
- 默认 `limit = 24`，最大 48；
- 按 `xumo_stories.updated_at DESC, story_id DESC` 排序并使用不透明游标。

`GET /api/public-stories/:storyId`

- 验证发布有效后，读取安全字段和当前修订；
- 同时返回当前访问者的公开阅读进度；
- 不存在、已取消、已下架或已归档统一返回 `404 public_story_unavailable`。

`PUT /api/public-stories/:storyId/progress`

- 保存当前登录读者的章节、滚动位置和期望版本；
- 版本冲突返回 `409` 及服务器最新进度；
- 小说不可公开读取时不接受新的进度写入，但已有记录保留。

### 9.3 管理员与举报

公开阅读页复用现有内容举报能力，并把公开小说 ID 作为目标。新增管理员发布状态操作：

- `POST /api/ops/publications/:storyId/suspend`；
- `POST /api/ops/publications/:storyId/restore`。

两者均要求管理员角色并写入审计事件。审计记录包含操作者、小说 ID、动作、时间和结构化原因，不保存完整正文。

## 10. 自动同步与一致性

- 公开详情查询通过 `xumo_chapters.current_revision_id` 连接当前修订。
- 新章节和修订必须在现有故事保存事务成功后才会进入公开查询结果。
- 生成任务失败或保存回滚时，`current_revision_id` 不改变，读者继续看到上一份成功正史。
- 发布与首次笔名设置使用事务，避免出现已公开但无笔名的中间状态。
- 取消公开先提交状态，再由后续请求判定；不依赖前端隐藏。
- 列表和详情响应设置 `Cache-Control: private, no-store`，避免登录态内容被共享缓存保存，也避免自动更新受陈旧缓存影响。

## 11. 权限与安全

- 分享 URL 中的 `storyId` 只是定位符，不作为授权凭据。
- 所有公开读取都同时验证登录、发布状态和故事状态。
- 发布接口在服务端重新验证所有权，不能依赖前端传入的 `ownerId`。
- 专用公开仓储只查询安全列；禁止先加载完整 `Story` 再通过对象解构删字段。
- 搜索、筛选和游标全部使用参数化 SQL 与输入长度限制。
- 生成段落按纯文本交给 React 渲染，不使用 `dangerouslySetInnerHTML`。
- 登录回跳只接受站内相对路径，防止开放重定向。
- 不在应用日志、审计事件或错误信息中记录完整小说正文。
- 未发布、被下架和不存在使用同一公开错误，降低枚举私有小说的能力。

## 12. 异常处理

- 未登录：返回 `401`，前端进入登录并保留安全的站内回跳路径。
- 非所有者发布或取消：返回 `403`。
- 笔名格式不合法：返回 `422 invalid_public_pen_name`。
- 小说无成功章节或已归档：返回 `409 story_not_publishable`。
- 管理员下架状态下重新发布：返回 `409 publication_suspended`。
- 公开作品不可用：统一返回 `404 public_story_unavailable`，页面显示“作品暂不可读”。
- 阅读进度版本冲突：返回 `409 progress_conflict` 和最新记录，前端以较新的版本为准。
- 进度章节已不存在：服务端按保存的章节编号选择不大于原编号的最近章节；若不存在则回到第一章，并把滚动位置重置为 0。
- 取消公开发生在阅读中：已加载文本保留在当前浏览器内，下一次详情、章节或进度请求被拒绝。
- 功能开关关闭：隐藏入口，发布与公开读取接口返回统一不可用响应；私人书架不受影响。

## 13. 前端组件边界

- `LibraryPage`：承载“我的书架 / 大家的故事”双入口，不直接处理公共查询细节。
- `PublicLibraryPage`：负责搜索、题材、分页与公共卡片。
- `StoryPublicationDialog`：负责笔名、公开预览、确认和错误反馈。
- `StoryPublicationActions`：负责公开状态、复制链接和取消公开。
- `PublicReaderPage`：专用只读页面，不通过条件分支复用包含作者能力的 `ReaderPage`。
- `publicStoryApi`：公开列表、详情和进度的前端接口边界。
- `PublicStoryRepository`：后端专用安全查询边界。
- `StoryPublicationService`：所有权验证、状态转换、笔名事务和审计。

专用只读页面和专用仓储能让权限边界通过结构保证，而不是依靠隐藏按钮或运行时删字段。

## 14. 测试策略

### 14.1 单元测试

- 发布状态的合法和非法转换；
- 笔名规范化与长度校验；
- 公开 DTO 字段白名单；
- 进度版本冲突和章节回退；
- 登录回跳路径过滤。

### 14.2 数据库与接口集成测试

- `004` 迁移可重复执行，已有故事默认私有；
- 发布记录所有权、外键和部分索引；
- 搜索、题材、最近更新排序、游标分页和上限；
- 未登录、错误所有者、已取消、已归档和管理员下架；
- 公开响应不含任何禁止字段；
- 发布与首次笔名设置的事务原子性；
- 多页面进度更新的乐观并发。

### 14.3 自动同步测试

1. 公开已有小说并读取当前章节；
2. 成功新增章节，确认公开详情与排序立即变化；
3. 成功修改旧章节当前修订，确认公开正文变化；
4. 模拟生成或保存失败，确认公开版仍为旧正史；
5. 取消公开后确认不可读且进度仍在；
6. 重新公开后确认原链接和进度恢复。

### 14.4 前端与端到端测试

- 书架双入口、搜索、题材和加载更多；
- 首次发布设置笔名、复制链接、取消公开；
- 登录后回到分享链接；
- 只读页面没有任何作者能力入口；
- 两个账号完成“作者发布和更新—读者搜索和阅读—保存进度—取消并重新公开”的完整流程；
- 私人书架、作者阅读页和生成流程的回归测试。

## 15. 上线与回滚

新增环境开关：

```text
PUBLIC_STORY_SHARING_ENABLED=false
```

上线顺序：

1. 备份数据库并执行兼容迁移；
2. 部署后端和前端代码，保持功能开关关闭；
3. 验证原有登录、私人书架和生成；
4. 使用两个测试账号完成发布与读取冒烟测试；
5. 打开功能开关；
6. 观察发布错误、公开读取错误、查询延迟和举报记录。

出现问题时先关闭功能开关，使入口和公开读取立即停止；新增表和可空列保留，不需要破坏性回滚，原有私人故事数据不受影响。

## 16. 可观测性

记录不含正文的结构化事件：

- 公开、取消公开、管理员下架和恢复；
- 公共列表与详情的状态码和延迟；
- 进度冲突数量；
- 公开接口的权限拒绝和字段序列化错误；
- 举报数量和处理状态。

不得记录完整段落、作者私有 payload、模型密钥或对话内容。

## 17. 验收标准

- 作者能设置统一笔名并立即公开含有成功章节的非归档小说。
- 另一注册账号能在“大家的故事”按标题或笔名搜索、按题材筛选并阅读。
- 未登录访问分享链接时，登录后返回同一小说。
- 读者只能取得当前正史正文，公开 API 不包含任何作者私有字段。
- 作者新增章节或提交旧章修订后，公开版无需再次发布即可读取新内容。
- 读者进度与作者进度相互独立，并能在取消、重新公开后恢复。
- 作者取消公开、管理员下架或归档后，列表和分享链接立即不可读。
- 原有私人书架、作者阅读、生成、模型连接和错误收集功能通过回归测试。
