# 故事永久删除设计

状态：设计已确认，待实施

日期：2026-07-30

范围：作者私有故事、故事档案页、PostgreSQL 与本地 JSON 持久化、公共书库关联、脱敏运营记录与回归测试

## 1. 背景与目标

当前产品只有“移出书架”：它把故事状态改为 `archived`，从书架隐藏，但仍保留故事正文、章节修订、公开记录和读者进度。用户需要一个含义明确的永久删除能力，用于彻底移除不再需要的故事。

本设计新增由故事所有者主动触发的永久删除。删除必须不可恢复、不可误触，并在一个原子操作中同时处理私人正史、公共阅读数据和可能包含故事内容的后台记录。产品仍保留不含标题、正文、提示词或上下文的脱敏审计与模型汇总指标。

## 2. 已确认的产品规则

1. 删除是永久操作，不进入回收站，也不提供用户自助恢复。
2. 删除入口只出现在“故事档案”页，不放在书架卡片上。
3. 用户必须手动输入完整故事标题；标题匹配后才能提交。
4. 已公开故事可以删除。删除成功后，公开书库条目和稳定分享链接立即不可读。
5. 删除同时清除作者正文、章节历史、读者公共阅读进度和所有可还原故事内容的后台数据。
6. 保留脱敏审计和模型统计，但不得保留故事标题、正文、候选文本、提示词、审核原句或公开链接。
7. 故事正在续写、修史、保存或等待用户审核时不得删除；不通过永久删除强制取消后台任务。

## 3. 方案选择

### 3.1 采用：同步事务永久删除

前端确认后调用所有者删除接口。服务端锁定故事、复核标题与并发状态，在一个事务内完成清理并返回 `204 No Content`。当前部署是单机 PostgreSQL，故事数据量适合同步删除；这种方案能够给用户明确、即时的最终结果。

### 3.2 未采用：标记后异步清理

异步清理需要新增删除状态、任务队列、失败补偿和后台观察。它适合超大对象或多实例平台，但会让“页面消失”和“数据已永久删除”成为两个时间点，不符合当前产品对即时反馈的要求。

### 3.3 未采用：继续使用软归档

软归档已经由“移出书架”提供，不能满足永久清除数据的目标。

## 4. 前端交互

### 4.1 入口

在故事档案页底部增加独立的“危险操作”区域：

- 保留现有“移出书架”；
- 新增红色“永久删除故事”按钮；
- 不在书架卡片、公共阅读页或普通阅读页放置删除入口。

删除任何状态的自有故事均使用同一入口，包括 `active`、`paused`、`completed` 和通过已知地址进入的 `archived` 故事。

### 4.2 确认窗口

点击删除按钮后打开专用确认窗口：

1. 明确列出将删除正文、版本历史、公开链接和读者进度，且无法恢复。
2. 展示需要输入的故事标题，但不自动填入输入框。
3. 用户输入去除首尾空白后必须与当前标题完全一致；英文大小写也必须一致。
4. 标题不匹配时，最终删除按钮保持禁用。
5. 提交后按钮显示“正在删除…”，关闭和重复提交操作暂时禁用。
6. 弹窗提供可访问名称、输入标签、初始焦点、键盘焦点约束和非提交状态下的 Esc 关闭。

删除成功后刷新全局书架，导航到首页，并显示“故事已永久删除”。失败时保留弹窗和用户已输入的标题，展示服务端返回的真实原因并允许重试。

## 5. API 契约与授权

新增接口：

```http
DELETE /api/stories/:storyId
Content-Type: application/json
Authorization: Bearer <token>

{
  "confirmationTitle": "完整故事标题"
}
```

处理规则：

- 未登录返回 `401`。
- 故事不存在或不属于当前账号统一返回 `404`，不泄露归属信息。
- `confirmationTitle` 去除首尾空白后与持久化标题不一致，返回 `400` 和稳定原因码 `story_delete_confirmation_mismatch`。
- 故事存在活动写入或活动生成任务时返回 `409` 和稳定原因码 `story_delete_busy`。
- 删除成功返回 `204`，响应体为空。

前端不得仅凭本地故事对象决定是否可删除。所有权、标题和忙碌状态均由服务端在删除事务中重新确认。

## 6. 并发与一致性

### 6.1 进程内互斥

删除复用现有 `storyMutationLocks`：

1. 如果故事已被续章、修史或其他正史操作锁定，直接返回 `409`。
2. 删除开始前把故事加入锁集合。
3. 在成功、校验失败或持久化失败后都通过 `finally` 释放锁。

新的正史操作在删除锁存在期间不得启动。

### 6.2 持久化事务

PostgreSQL 删除方法必须：

1. 以 `owner_id + story_id` 查询并 `FOR UPDATE` 锁定故事行。
2. 在锁内再次校验标题。
3. 查询该故事是否仍有 `running` 或 `awaiting_user_review` 任务。
4. 完成内容清理、运营记录脱敏、故事删除、当前故事指针更新和删除审计。
5. 任一步骤失败时回滚整个事务。

本地 JSON 模式在现有文件存储写入门禁内完成同样的内存变更，再原子保存；保存失败时恢复删除前快照。

## 7. 数据删除与保留

### 7.1 必须永久删除

删除 `xumo_stories` 主记录，并依赖或显式验证关联清理：

- `xumo_chapters`；
- `xumo_chapter_revisions`；
- `xumo_story_creation_requests`；
- `xumo_story_publications`；
- `xumo_public_reading_progress`；
- 与该故事相关的内容举报；
- 与该故事任务相关、可能含候选句或正文的叙述审核 case；
- 与该故事相关、可能含原文判断内容的安全决策。

公开记录和公共阅读进度必须与故事在同一事务中消失。删除提交后，旧私人地址与公开分享地址都返回不可用。

### 7.2 可以保留的脱敏统计

完成或失败的生成任务可以保留以下字段：

- 任务类型与最终状态；
- 模型、连接标识和提示版本号；
- Token、费用、耗时和首字延迟；
- 尝试次数、错误类别、稳定原因码和是否重试成功；
- 创建时间及不含业务内容的接受信号。

保留记录必须执行以下清理：

- `storyId` 改为固定删除占位符，不保留可形成故事链接的标识；
- `storyTitle` 改为“已删除故事”；
- 移除幂等键、候选轨迹、筛选摘要、上下文轨迹、修史 ID 和事件 ID；
- 失败消息改为固定脱敏说明，仅保留结构化原因码；
- 清除叙述审核反馈中的同意摘录密文和到期时间；叙述审核 case 本身删除；
- 既有故事审计元数据替换为不含业务内容的删除占位信息。

新增 `story.deleted` 审计只保留操作者、时间、动作和布尔型范围信息，例如删除前是否公开、是否为当前故事；不得保存标题、章节名、正文、公开 ID 或提示词。

### 7.3 内存状态

提交成功后同步更新运行时状态：

- 从 `store.stories` 移除故事；
- 清除所有用户指向该故事的 `activeStoryId`；
- 移除对应的故事创建请求、安全决策和内容举报；
- 将任务与失败记录替换为相同的脱敏形式；
- 保留并加入脱敏删除审计。

该顺序避免后续 `saveSnapshot` 从旧缓存重新写回已删除故事或未经脱敏的运营记录。

## 8. 短暂断线与结果确认

如果 `DELETE` 请求因网络错误而没有收到响应，前端不得立即宣告失败。它应自动请求一次私人故事详情：

- 详情返回 `404`：说明删除已提交，按成功处理并返回书架；
- 详情仍可读取：说明删除没有完成，保留确认窗口并提示重试；
- 返回 `401` 或其他错误：显示该真实错误，不猜测删除结果。

服务器端重复请求不会影响其他故事；故事已经删除后继续访问统一返回 `404`。

## 9. 组件与代码边界

实现分为四个明确单元：

1. `StoryDeletionDialog`：只负责警告、标题输入、可访问交互与提交状态。
2. 前端删除协调器：调用 API，并在网络错误时执行存在性确认；不负责数据库语义。
3. 存储层 `deleteOwnedStory`：提供 PostgreSQL 与 JSON 一致的事务语义、数据清理和返回结果。
4. 路由处理器：负责认证、参数校验、进程内锁和 HTTP 状态映射。

删除清理的纯数据转换应集中在单独函数中，供 PostgreSQL、JSON 存储和测试共同使用，避免两套脱敏规则逐渐分叉。

## 10. 测试设计

### 10.1 领域与前端协调测试

- 标题完全匹配才允许提交；首尾空白可忽略，内部字符和大小写不可忽略。
- 脱敏转换移除标题、候选轨迹、上下文、失败消息和内容关联 ID，同时保留模型汇总字段。
- `DELETE` 响应丢失后，详情 `404` 被解释为成功；故事仍存在时解释为失败。
- 删除提交期间不能重复提交或关闭确认窗口。

### 10.2 API 测试

- 未登录返回 `401`。
- 非所有者和不存在故事返回相同 `404`。
- 标题不匹配返回 `400 story_delete_confirmation_mismatch`。
- 活动写入、运行任务和等待审核任务返回 `409 story_delete_busy`。
- 成功返回 `204`，当前用户再次读取故事得到 `404`。
- 删除其他故事不会改变当前故事指针。

### 10.3 PostgreSQL 集成测试

- 故事、章节、修订、创建请求、发布记录和所有读者进度在同一事务中删除。
- 内容举报、安全决策和含内容的叙述审核 case 被删除。
- 叙述审核反馈不再包含摘录密文。
- 生成任务和失败观测仍可聚合，但不能查询到原故事标题、故事 ID、候选内容、上下文或原失败消息。
- 既有审计和新增删除审计均不含故事业务内容。
- 所有者 `active_story_id` 正确清空。
- 注入中途 SQL 失败时，故事和全部关联数据仍存在，证明事务回滚完整。

### 10.4 JSON 存储与回归

- JSON 模式完成与 PostgreSQL 相同的数据删除和脱敏。
- 文件写入失败时恢复完整删除前状态。
- 书架分页总故事数和总章节数立即减少。
- 公开列表、公开详情和公共进度接口不再读取已删除故事。
- 全量 `npm test`、`npm run typecheck` 和 `npm run build` 通过。

## 11. 发布与回滚

- 本设计不新增 SQL migration；使用现有表、约束与事务完成删除和脱敏。
- 部署前创建并验证 PostgreSQL 自定义格式备份。
- 部署后先用专用测试故事验证私人删除、公开链接失效、读者进度清理和脱敏运营指标。
- 代码回滚不会恢复已经永久删除的数据。回滚前必须明确这一事实；只有生产事故恢复才可以由管理员使用部署前数据库备份整体恢复，不能提供单本故事自助恢复。

## 12. 实施边界

本次包含：

- 故事档案页永久删除入口与标题确认窗口；
- 所有者删除 API；
- PostgreSQL 和 JSON 存储一致的事务删除；
- 公共分享、读者进度和内容关联数据清理；
- 运营记录脱敏保留；
- 短暂断线后的结果确认；
- 自动化测试与发布前备份验证。

本次不包含：

- 回收站或延迟删除；
- 管理员代用户删除；
- 批量删除；
- 自动取消正在运行的生成任务；
- 从备份恢复单本故事；
- 书架卡片或公共阅读页删除入口。

## 13. 验收标准

1. 删除按钮只出现在故事档案页，并要求输入完整标题。
2. 忙碌故事不能删除，提示具体且不会中断后台任务。
3. 成功删除后私人故事、全部章节修订、公开链接和读者进度立即不可读。
4. 删除操作要么完整提交，要么完整回滚，不产生半删除状态。
5. 后台仍能汇总模型质量与成本，但无法从保留记录恢复标题、正文、提示词、候选内容、审核原句或故事链接。
6. 删除当前故事后书架状态和当前故事指针正确更新。
7. 网络响应丢失时，前端通过存在性查询给出真实结果。
8. PostgreSQL 与 JSON 存储行为一致，完整测试、类型检查和生产构建通过。
