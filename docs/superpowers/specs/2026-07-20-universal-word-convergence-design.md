# 任意体验词通用出书与中途改意图设计

状态：已确认

日期：2026-07-20

范围：开书、续章、验收、连续性、换词与改思路；替代按词特化的门禁与提示词

关联：细化并部分修订《2026-07-17 任意阅读体验词稳定兑现设计》。该文档的 `compile` / `schedule` / `assess` 三入口架构、数据模型（契约修订、激活记录、账本）、错误分类全部保留；本设计修订其 §10.3 中"现有正则可封装为规则 Adapter"的保留意见，并给出以收敛为目标的验收与重写机制。

## 1. 需求（纠正后的产品承诺）

**读者输入任意两个体验词 + 一段灵感思路，系统都能开书并持续续写；写作过程中读者可以随时更改后续思路（包括换体验词、改方向偏好），系统从下一章起兑现新意图，不重写已发布正史。**

"系统 · 无敌"只是历史测试用例，不是需求本体。任何按具体词语启用的代码路径都是对单词的过拟合，违反本需求。

### 1.1 验收标准（五条）

1. **通用兑现**：不存在任何按具体词语启用的代码分支、提示词模板、固定开头骨架、本地兜底段落。词语的全部语义只存在于编译出的契约数据里。判据：`compile` 实现之外全库搜不到 `sourceWords.includes("某词")`、`word === "某词"` 等词面分支。
2. **可收敛**：任意被接受的词对，生成作业在有限重试内以高概率产出可发布章节（`job_success_rate ≥ 4/5`，沿用 7-17 §12.3）。不允许靠给单词写专属正则或骨架达标。
3. **忠实读者意图**：正文符合两个词的语义与灵感思路中的关键设定；验收证明语义兑现，不要求关键词逐字出现。
4. **可持续续写**：跨章不丢失已建立的能力、关系、状态；对任何词都成立。
5. **中途可改**：换词、改思路通过新契约修订 + 激活记录从下一章生效；旧章节不被追溯判失败。

一句话判据：**删掉代码中对"系统""无敌"四个字的全部特化后，这两个词的书写得不比以前差——因为它们只是策展词表中普通的两个。**

## 2. 问题：现状为什么既不通用也不收敛

现状是"三等公民"体系：

| 等级 | 词 | 现状 |
|---|---|---|
| 特权词 | 系统、无敌 | 专属散文正则门禁（约 800 行）、开篇固定三句骨架、专属提示词段、专属本地兜底章节、专属初始知识 |
| 策展词 | 其余约 30 个 | 有人工定义，走通用信号验证 |
| 未知词 | 任意其他输入 | 退化为"主角行动"解释 + n-gram 锚点逐字匹配验证 |

两个结构性缺陷：

1. **验证手段与验证对象错配。**"主角压倒性获胜"这类语义命题的合格表达空间是开放的，正则枚举（动词表、姓氏表、24/30/40 字否定前缀窗口）只覆盖其中一小块，且模型看不见这个"通过区域"。每稿通过是低概率抽样；失败错误描述的是意图，真实拒因是措辞没踩中正则，模型按意图修复仍然踩不中；整章重抽两次等于两次独立低概率抽样。每个正则补丁修一个误杀、造一批新边界，且只对被特化的词生效。
2. **写作指令与验收标准不对齐。** 提示词承诺"正文不必出现体验词"，锚点机制却要求 quote 逐字包含由信号描述切出的 n-gram 短语；对未知词，这把语义验证降级成关键词匹配，是未知词不收敛的主因。

固定骨架能让特权词 100% 过门禁，但每本书开头一模一样、盖过用户灵感的开场设定，直接违反标准 1 和 3——它是掩盖缺陷 1 的止痛药，不是修复。

## 3. 设计原则

1. **在结构上做硬校验，在散文上做软裁判。** 确定性检查只保留高精度、词无关的集合；语义判断交给独立裁判模型按契约量表评分。
2. **写作模型必须看到与验收同源的标准。** 裁判用的契约文本逐字进入写作提示词，消除"按 A 写、按 B 判"。
3. **修复是定向补丁，不是整章重抽。** 每轮只重写失败信号映射的段落，使迭代单调收敛。
4. **每条执行路径终止于明确结果**：通过 / 带债通过 / 可解释失败（附换词建议），不存在"重试耗尽 + 无出路"。
5. **正面承诺是分数与账本，负面禁忌才是布尔。** 布尔硬门禁只保留极少数高精度负面不变量。
6. **词语语义是数据，不是代码。** 策展词与未知词走同一条执行路径，区别只在契约内容的来源（人工策展 vs 模型解释）与置信度。

## 4. 需要拆除的特化点清单

以下均为按词特化、违反标准 1 的代码，随阶段 2 删除或转成契约数据：

- `server/readingExperience.ts`：`isSystemInvincibleExperience` 及其 4 处调用；`usesSpecializedDeterministicGate`（word === "系统"/"无敌" 时跳过模型信号合并）。
- `server/narrativeEngine.ts`：`assertReadingExperienceNegativeInvariants` / `assertPersistentExperienceFacts` / `assertReadingExperienceContent` / `groundReadingExperienceEvidence` 中共约 10 处词面分支；背后的 `hasDominantProtagonistVictory`、`hasProtagonistSystemInteraction`、`hasSystemAvailabilityFailure`、`hasActualProtagonistSystemPayoff`、`hasActualWorldReaction`、`hasDominantVictoryWithImmediateReaction` 等散文语义正则（含姓氏表、否定窗口、梦境检测、代理胜利检测）；`buildChapterPrompt` 中的 `systemInvincibleActionChain` 第二章硬编码动作链。
- `server/modelGateway.ts`：`specializedOpeningInstructions` 三段（含"系统无敌首段固定三句骨架"）。
- `server/storyService.ts`：`systemInvincibleParagraphs` 18 段硬编码本地章节、`experienceGene` 专属故事基因、`initialKnowledge` 专属分支。
- 对所有词有害的通用机制：`deriveSignalEvidenceAnchors` n-gram 切词、`hasIndependentSignalEvidenceAnchors`、quote 逐字包含锚点要求、`groundReadingExperienceEvidence` 的候选句相似度替换。
- 第二章连续性散文正则 `hasPriorPersistentFactContinuity`。

## 5. 目标架构

```
用户词对 + 灵感思路
        │
        ▼
compile（沿用 7-17）
  词义解释 → 双维度契约 + 裁判量表（rubric）
  灵感抽取 → 创作约束清单（短句事实，标记关键项）
        │
        ▼
plan（结构化硬校验层）
  规划产出本章节拍/信号安排（结构化 JSON）
  确定性校验字段值：轴覆盖、位置窗口、主语、结果时态、
  关键灵感条目被引用、上一章持久事实被引用
  失败 → JSON 修补（可靠、便宜）
        │
        ▼
write
  提示词 = 契约量表原文 + 本章安排 + 创作约束 + 沉浸叙事要求
  返回正文 + 信号映射（每信号 → 段落号 + ≤60 字短引文）
        │
        ▼
assess 两级验收
  L1 确定性（布尔，词无关）：字数/段落带宽、安全、元叙事词表、
     感觉词直拼景物、引文归一化模糊包含、位置校验、两轴不复用同句
  L2 语义裁判（评分）：每信号 0–2 分；不足 2 分必附
     指向具体段落的可执行修复指令；裁判提示 = 写作提示同源契约文本
        │
        ▼
repair 阶梯（收敛保证）
  定向补丁 ×2（只重写失败段落，重跑 L1 + 受影响信号的 L2）
  → 修订本章安排后整章重写 ×1
  → 软承诺未满：记体验债，带债发布
  → 硬承诺未满：作业明确失败 + 换词/调整灵感建议，不污染正史
```

### 5.1 量表（rubric）

每个体验维度编译出 3–5 条评分项，每条含 0 分 / 1 分 / 2 分的特征描述。策展词量表人工维护；未知词由解释模型起草、经结构校验入库。现有"系统""无敌"正则的语义改写为量表条目，例如：

- 无敌 2 分：主角亲手在正面冲突中获胜，对手明确失去反抗能力，同段或下一段出现旁观者/势力/资源/秩序的已发生反应。
- 无敌 0 分：胜利只出现在宣言、计划、梦境、模拟中；或由他人代打；或与对手五五开。
- 系统 2 分：主角本人触发机制并获得改变行动或资源状态的持续反馈。
- 系统 0 分：机制只是比喻或旁白；默认故障、拒绝结算、奖励撤回。

### 5.2 裁判

- 独立调用（extractor/reviewer 路由），输入 = 量表 + 本章安排 + 信号映射 + 正文；输出结构化 `{signalId, score: 0|1|2, reason, fixInstruction?}`。
- 裁判无权改契约，看不到写作模型自评（沿用 7-17 §8.2）；输出过结构校验，一次 JSON 修补重试。
- 通过线：到期硬承诺信号 = 2 分；其余均分 ≥ 1.5。
- 防放水：≥10% 样本双裁判或人工复核（沿用 7-17 §12.3）；每章信号映射与裁判判词随章节修订持久化，供修史重放与抽查。

### 5.3 连续性与体验债

- 上一章持久事实（来自当前修订的正史事件与知识来源，即现有 `selectPriorPersistentContinuityFacts` 的选取逻辑）作为输入进 plan 与写作提示；plan 校验至少一处引用；裁判量表含通用评分项"本章在使用而非遗忘既有资产"。
- 落地体验债：`maxSilentChapters` 放宽为软承诺可欠债、补偿窗口内偿还；带债发布时债务（轴、缺口、窗口）写入账本，下一章 plan 自动生成补偿安排，窗口末章升级为硬承诺。开篇两章与卷级里程碑的硬承诺不可转债。

### 5.4 中途改意图

- **换体验词**：新 API 走 `compile` 生成新契约修订 + 新激活记录（`effectiveFromChapter = 当前章 + 1`），旧激活通过关闭记录界定范围（数据模型沿用 7-17 §5.2）；账本从新起点重建到期承诺；旧章节不追溯判失败。
- **更新后续思路**：读者提交新方向，经安全预检后进入故事级"方向约束"，在候选规划与写作提示中与灵感同级注入；与偏好系统（否决/喜好）区分。
- 两者均不触发修史；修改已发布内容仍走 retcon 流程。

## 6. 实施计划（五阶段，每阶段独立可验证）

### 阶段 0：立标尺

- 建词类测试矩阵：每个信号类别（机制/冲突结果/关系/文风/节奏/世界反应）1–2 个词 + 未知词（如"赛博修仙"）+ 冲突词对（"治愈 · 残酷"）+ 重复词对（"温暖 · 温暖"）。"系统 · 无敌"是矩阵中普通一行。
- 用真实模型连接对矩阵跑现状基线，记录 `job_success_rate` / `published_compliance_rate` / `chapter_two_retention_rate`（定义沿用 7-17 §12.3）。

### 阶段 1：语义验证翻转为裁判评分（解收敛）

- L1 收缩为高精度词无关集合；实现量表裁判与信号映射；删除 n-gram 锚点机制；重写策略改为定向补丁阶梯。
- 涉及：`narrativeEngine.ts`（验证函数群）、`modelGateway.ts`（开篇/审稿循环）、`index.ts`（续章质量循环）。

### 阶段 2：特权词降级为普通策展词（解通用）

- "系统""无敌"语义改写为量表数据；删除 §4 清单中全部特化点。
- 位置要求改为从契约投影的通用形式（如"每个体验轴在前 15% 内出现首个可观察信号"）。
- 本地无模型兜底保留为演示用途，按 7-17 §9 明确标记"未经体验验收"，不为任何词伪装成功。
- 完成判据：矩阵中"系统 · 无敌"一行指标不低于其他策展词。

### 阶段 3：连续性与体验债通用化（解续写）

- 删除 `hasPriorPersistentFactContinuity`，按 §5.3 改造；落地体验债与补偿窗口。

### 阶段 4：中途改意图（补功能）

- 按 §5.4 新增换词 API 与方向约束入口及前端。

### 阶段 5：清理与防回归

- CI 门禁：grep 禁止 `compile` 实现之外出现 `sourceWords.includes(`、`word === "` 词面分支（7-17 §12.4 的具体化）。
- 修订 7-17 §10.3 首行保留意见：正则不封装为规则 Adapter，直接由量表替代。
- 用阶段 0 矩阵做最终验收，对照基线出报告。

### 顺序依据

阶段 1 必须先于阶段 2：先有裁判承接语义验证，再拆正则，避免拆除期间无验收裸奔。阶段 3–4 可与阶段 2 并行。

## 7. 风险

- **裁判放水或不稳定**（最大风险）：对策见 §5.2；阶段 0 基线使放水可被数据发现。
- **成本**：裁判是新增调用，但定向补丁替代整章重写后，单次成功作业总 Token 预期下降；`generationBudget` 预算门全程保留，作用于阶梯每一步。
- **迁移期回归**：阶段 1 可先以 shadow 模式并行运行新旧两套验收（新套记录不阻断），对比分歧率后再切换，最后删除旧门禁。

## 8. 验收指标

- `job_success_rate ≥ 4/5`（矩阵每行）。
- `published_compliance_rate = 100%`（已发布章节全部有双维度证据）。
- `chapter_two_retention_rate ≥ 90%`。
- 误杀率（人工判定合格却被拒）< 5%。
- 忠实度抽样人工评估不低于现行通过稿。
- 词面分支 grep 为零（`compile` 之外）。
